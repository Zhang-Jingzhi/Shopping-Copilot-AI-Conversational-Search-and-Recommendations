1. 执行摘要

该包提供一份可本地复现、可审计的扩展数据集。它严格匹配公开 200 的会话字段契约，并保留可验证的场景、难度与 profile 文本规律。它不是 private 800 的复原：官方未发布真实用户、时间、历史评分序列、标签生成算法或私有商品身份。

正确使用边界：把它当作本地训练、回归和分层分析的代理集；不要把质量层写成 private 标签，也不要把低可能层当负例。对用户 profile 中没有直接依据的字段，只能作接口兼容或分布代理，不可当作事实。

3. 来源与构建流程

Amazon Reviews 2023→5-core LLO test→冻结 50k 商品目录→3,221 个目录-test 目标→排除公开 200→3,021 条扩展会话→四层共识分层
  1. 扫描 2,524,981 条 LLO test 记录，收集 catalog 目标的 test 互动与评分。
  2. 排除公开 200 个目标商品；为剩余 3,021 个商品各生成一条会话。
  3. 以公开 200 的场景比例、难度映射和 profile 可观察规律进行确定性分配。
  4. 真实用户、时间、用户历史评分序列与偏好标签均不可得；因此不从 history 的 ASIN 序列伪造这些信息。
  5. 所有样本通过未修改 evaluator 的隐藏 intent/behavior materialization 验证。
  6. 按产品选择规则共识频率生成 sidecar 分层，不修改官方会话 schema。

商品大类（category_bucket）直接可见采用公开集观察到的固定值不得声称 private 800 也必然全为同一取值。
难度桶（difficulty_bucket）公开集规律按公开集观察到的映射生成不得声称已获得组织方内部难度标注过程。
目标商品家族 ID（ground_truth.parent_asin）直接可追溯验证 catalog 成员资格与目标唯一性不得把任一非公开目标称为 private 800 商品。

会话场景（scenario_type）公开集分布规律按公开比例和固定随机种子分配不得声称某个商品在官方数据中属于该场景。
用户历史平均评分（average_prior_rating）公开分布 + 目标互动评分代理没有可用的用户历史评分序列；仅缩放公开边际分布，并要求代理值在该目标 test 互动中存在不得称其为真实用户历史平均分，不得用作用户画像或偏好标签真值。
用户偏好标签（preference_tags）无直接依据源用户、时间与标签算法未公开，因此显式置空而不猜测不得将空列表理解为用户没有偏好；不得由商品标题自动补造标签并称为官方风格。
历史购买频率（purchase_frequency）公开集常量采用公开集观察到的固定文本不得声称每个扩展样本对应的真实用户确有 3–4 次历史购买。
评分风格（rating_style）公开集规律 + 代理值派生由平均评分字段确定性映射不得称为真实用户的评论语气或稳定行为特征。
用户摘要（summary）模板规律 + 不可得标记显式标记不可得信息，绝不猜测标签不得将该摘要用于推断真实用户偏好。
评分概念不得混用：average_prior_rating 是用户历史平均评分字段；average_rating 是商品 metadata 的商品平均星级；rating_number 是商品 metadata 的评论/评分数量；test 行中的 rating 是该条目标互动的单次评分。四者不是同一个量。

5. 质量分层

层级来自 100 个在公开覆盖上表现较强的合理筛选模型的跨模型入选频率。它衡量“与已知官方选择模式相似的程度”，而不是 private 800 的身份概率。

评分在分层中的实际作用：最终四层共识使用商品评论/评分数量 rating_number 的同类百分位、test 目标交互量、最长历史长度、历史长度≥13 的覆盖量及 metadata 完整度。商品平均评分 average_rating 只出现在早期阈值诊断，不参与最终四层共识；用户历史平均评分 average_prior_rating 完全未进入分层代码；test 单次互动 rating 也未进入最终共识评分。

6. 复现、局限与包边界

  • 生成代码：scripts/generate_contract_matched_sessions.py；筛选分层代码：scripts/infer_quality_filter.py。
  • 包内 manifest 记录每个文件 SHA256，以及未复制的大型上游输入的路径与 SHA256。
  • 包不复制 50k catalog 与 252 万 test 行，避免重复大型上游数据；它们仍可按 manifest 精确定位。
  • 包不含 retrieval、Dense、bad-case 结果，符合当前数据交付范围。
构建校验：3,021 条生成会话；3,021 条 evaluator materialization 成功。报告由包内 manifest 与数据文件共同支撑。
